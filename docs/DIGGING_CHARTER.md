# DIGGING CHARTER -- binds EVERY external-search operator (present + future)

_Prospector, Literature Deep-Miner, OSINT scanner, Crisis Autopsy, and any future digger obey ALL of this. Freeze-subject: modifiable only by the monthly engine. No change to governance, budget caps, or card limits -- this sets POSTURE, not volume._

## 1. LANGUAGE-BLIND
Information value is independent of language. Queries, source filtering, and digest processing must NOT favor English. A mechanism or risk signal in Chinese, Russian, Korean, Japanese, or any language is found, translated, and evaluated on equal footing. Language is NEVER a reason to discard a lead. Understanding and implementing the value is all that matters -- not the language it arrived in.

## 2. GITHUB MAXIMALISM
Every search cycle includes GitHub as a PRIMARY source: repositories, READMEs, Discussions, AND Issues -- these hold unreleased trading systems, backtests, config patterns, and technical deep-dives published nowhere else. Search quant trading bots, algorithmic strategies, alpha research, execution tools, HFT/MM infra, and related projects. Follow forks, stars, and cross-references to uncover hidden gems. A 2-star repo with a broken README may hold a better edge than a top journal.

## 3. BREADTH AND DEPTH MAXIMIZATION
Default is to exhaust BOTH. Cast the widest net (breadth) then follow promising leads as deep as the citation/thread/fork chain allows (depth). Depth trade-in favors deepening when early results are sparse, but never stop expanding breadth if novel information surfaces. The session metric is MAXIMUM INFORMATION GAINED = count of previously-unknown, economically-plausible mechanisms or risk signals uncovered. Most information gained, to the core, always -- hunt the most valuable information everywhere, every breadth, every depth reachable online.

## 4. INFORMATION VALUE OVER SOURCE PRESTIGE
Judge every finding SOLELY on the mechanism's plausibility, falsifiability, and potential impact. Source prestige is irrelevant. No source class (papers, GitHub, forums, books, patents, conferences, blogs, podcasts, non-English) is assumed to dominate permanently.

## 5. THE SEARCH ENGINE IS A SELF-OPTIMIZING ASSET
Every cycle is evaluated on discoveries AND on how to improve FUTURE discovery. Measure each source class by historical VALIDATED information gain (source-yield learning); allocate more budget to what yields while keeping minimum exploration across underrepresented classes. Assume valuable information exists OUTSIDE the current search universe -- continuously discover new communities, repos, databases, conferences, journals, languages, and knowledge networks not yet monitored. The universe is NEVER complete (coverage-completeness audit). Every cycle names unanswered questions, weakly-supported assumptions, and underexplored areas -- these become first-class search targets until resolved or deprioritized by evidence.

## 6. CROSS-DOMAIN TRANSFER
Any field capable of improving alpha discovery, execution quality, robustness, infrastructure, or scientific methodology is IN SCOPE. Actively transfer ideas across disciplines when economically plausible and empirically testable (drug-discovery pipelines, ad-tech experimentation, genomics multiplicity, sports analytics, etc.).

## 7. SYNTHESIS OBJECTIVE
Highest EV often comes from COMBINING independently-validated mechanisms from different disciplines/communities, not isolated discoveries. Prioritize synthesis and recombination alongside discovery; generate new hypotheses from connections between previously separate ideas (the synthesize mission, applied continuously).

## 8. EXTREME CLAIMS
Extraordinary performance claims receive HIGHER RESEARCH PRIORITY (high expected value of investigation) but NEVER higher evidential CREDIBILITY from the claim itself. Convert every claim to testable hypotheses, prioritize by expected information gain, accept/reject SOLELY on reproducible empirical evidence. No economically-plausible idea is ignored for where it came from, what language it is in, or how extraordinary its claim.

PRIMARY OBJECTIVE: maximize cumulative VALIDATED information gain over time -- by improving source coverage, query generation, source discovery, citation exploration, multilingual understanding, and triage quality -- while preserving exploration to discover entirely new edge areas. All findings flow to the same triage: EV gate -> pre-registration -> gauntlet -> forward shadow. Discovery is aggressive and boundless; PROMOTION is empirical-only.

## 9. COMMENT / REPLY LAYER IS FIRST-CLASS
The gold is often NOT the original post -- it is the reply. Ex-quants comment more than they
post; the real mechanism, the refinement, and the debunking live in the thread, not the
headline. Mine GitHub Issues + Discussions, forum reply chains, Reddit/X/YouTube comment
threads to their depth (>=2 levels). The BEST comment can outrank the OP. And mine DEBUNKING
replies as pre-emptive falsification -- "this fails because costs/crowding/look-ahead" is a free
graveyard entry that saves a test slot. Read the whole discussion, always.

## 10. CRYPTO-NATIVE SOURCE FAMILY (first-class -- the desk is crypto-only)
Heavily weight crypto-native sources: crypto Twitter/fintwit; crypto media (Rekt News, DL News,
The Block, Messari, Delphi, Glassnode/CryptoQuant blogs); crypto GitHub frameworks (Hummingbot,
Freqtrade, Jesse, MEV/searcher bots, perp-DEX + DeFi protocol repos + their Issues/Discussions);
crypto communities (r/defi, r/ethfinance, r/CryptoCurrency, Discords/Telegrams, TradingView
crypto ideas); perp-DEX / on-chain mechanism communities (Hyperliquid, GMX, funding-arb,
liquidation-hunting, airdrop/farming); and NON-ENGLISH crypto (Chinese/Korean/Russian/Arabic/
Portuguese -- see the frontier packages in the improvement inbox). Crypto-native edges
(funding, liquidations, basis, unlocks, listings, MEV, governance events) are the center of
gravity.

## 11. NEW DATA SOURCES ARE A LOGGED PER-DIG DELIVERABLE
Every dig also hunts new FREE DATA sources (exchange dumps, free APIs, community data lakes,
data-collector repos, in any language) -- and logs anything found to data/data_universe_map.json
as an explicit deliverable, not an afterthought. Data discovery is dug as deep as edge discovery
and governed by the free-first protocol.

## 12. SEARCH-SPACE EXPANSION (universal standing rule — ALL expansion miners & diggers)

The source universe is assumed PERMANENTLY INCOMPLETE. Every digging session reserves a defined portion of its exploration budget to discover entirely NEW source classes: communities, repositories, conferences, public datasets, developer ecosystems, APIs, documentation sites, archives, regional knowledge networks, and other previously-untracked information ecosystems. Newly discovered classes are evaluated, catalogued, and folded into future search cycles ONLY on demonstrated validated research value. Sources with sustained low validated information gain, persistent quality issues, or repeated failures may be deprioritized or retired — but remain ARCHIVED in the Data Universe Map for historical reference. Retirement is evidence-based and REVERSIBLE if new evidence emerges (see Temporal Rediscovery). This rule binds every digger present and future: the strategy Prospector, the Literature Deep-Miner, the Free-Data-Alternatives mission, Blind Rediscovery, and any future miner. Obscurity is never itself evidence of value; empirical validated quality is the only currency.

## 13. LICENSE / LEGITIMACY GATE (universal — ALL diggers, mandatory)

Adopt ONLY sources with a clear permitted-usage license. The desk NEVER seeks, downloads, executes, or adopts: pirated or 'shared' paid datasets; cracked / keygen'd / shared-account premium software or trading platforms; paywall-circumvented papers or books; or community mirrors of paid institutional databases (CNKI, Wind, Wanfang, Bloomberg, Refinitiv, etc.). This STRENGTHENS Data Genealogy, and the reasons are practical, not only legal: (1) a signal built on data the desk has no right to use is UN-DEPLOYABLE at live/commercial scale — it must be ripped out later, so it is worthless now; (2) cracked software from forums / Baidu Cloud / Telegram is a top malware vector and MUST NEVER run on the box that holds the desk's keys, ledger, and eventually live-trading credentials — a hard security boundary; (3) pirated/modified datasets carry exactly the fabrication/mislabel risk that manufactures phantom edges. Illegitimate finds are logged in data_universe_map.json graded 'excluded-illegitimate' (awareness only, so they are not re-encountered blind) and NEVER adopted or downloaded. Legitimately-free (open-source, exchange-native, open-data, open-access) != pirated; Free-First means the former only.

**CJK open-source is a standing HIGH-YIELD priority** for all diggers (operator 2026-07-19): the Chinese-language internet (Gitee, Chinese GitHub, open community datasets, open-access academic) carries a disproportionately large layer of LEGITIMATELY-free quant resources English-only research never sees — a genuine structural edge. Language-blind digging already mandates it; this elevates it. Strictly subject to §13's legitimacy gate above.

**Publicly-shared data — EVALUATE, never blanket-skip (operator 2026-07-19):** data posted on forums / comments / file-hosts / community lakes is assessed on its LICENSE, not dismissed for where it appeared. Genuinely-open finds (free tiers, vendor samples, open/CC/public-domain licenses, publicly-released subsets) are ADOPTED. Raw FACTS a vendor merely repackages (on-chain, exchange APIs) are free to collect directly (facts are not copyrightable; the vendor's curated product is) -> reconstruct. A genuinely-proprietary LEAKED file is not adopted into a live signal (un-deployable + contamination) BUT its information is not ignored: read what it is, then reconstruct its research-valuable component from public raw (vendor-replacement). The gate is SURGICAL -- it blocks ADOPTING proprietary/cracked material, never an excuse to skip legitimately-usable shared data. No good information is left on the table.

## 14. DIGGER PARITY & UPGRADE PROPAGATION (universal — no digger left behind)

The diggers are ONE FAMILY and advance TOGETHER. Every digger/miner maintains EQUIVALENT depth, breadth, language/region coverage, verification rigor, cadence-reliability, and capability — each in ITS OWN domain equivalent (the data miner's regions are regional exchange/on-chain ecosystems; the strategy Prospector's are regional quant-CODE ecosystems — Gitee + Chinese GitHub quant repos/factor libraries/backtest frameworks, Korean/Japanese/Russian/CIS algo communities; the Literature miner's are non-English academic + methods venues and open-access mirrors). LANGUAGE-BLIND + REGION-RICH (CJK + Korean, Japanese, Russian/CIS, Arabic, Portuguese, and every frontier) applies to ALL of them, not just the data mission. UPGRADE PROPAGATION (standing rule): whenever ANY digger is upgraded — deeper depth, a new source class, a new region/language layer, a new technique, a new cadence/reliability mechanism (e.g. a dedicated timer) — the SAME upgrade is applied to EVERY other digger where it has a meaningful equivalent, in the same cycle. No digger is left behind or allowed to drift ahead: if one gets a dedicated timer, all do; if one gets uncapped exhaustive depth, all do; if one gains a regional-language layer, all gain their equivalent. Goal: max out data + strategies + information gathering as exhaustively as possible across the whole family, uniformly. Parity is audited in the quarterly Coverage-Completeness Audit; any digger lagging another is brought to par that cycle.

## 15. SEARCH OPERATOR LIBRARY (single source of truth for ALL search capability)

The desk maintains ONE growing library of validated search capability: search operators, query
templates, multilingual search patterns, citation-following techniques, repository-discovery
strategies, source-expansion heuristics, community-discovery methods, verification protocols,
and data-reconstruction approaches. Canonical home: `docs/research/search_operator_library.md`
(git = the versioning; every prior version recoverable), pointered from
`data/data_universe_map.json`. Operators are evaluated on VALIDATED information gain and
continuously refined, combined, or retired (retired entries stay archived, never deleted).
Every digger, miner, and expansion — present and future — DRAWS from this library equally at
the start of every session and CONTRIBUTES back to it before the session ends. The library is
seeded with region-specific, non-English operators (Yandex for Russian, Baidu for Chinese,
Naver for Korean, Yahoo!JP for Japanese, plus Arabic and Portuguese forum patterns) and
expands with every new language/region added to the search surface. No digger maintains a
private operator collection: capability lives in the library or it does not exist.

## 16. CROSS-DIGGER UPGRADE PROPAGATION — MECHANICS (extends §14; permanent, self-enforcing)

When ANY digger/miner/expansion develops or discovers a capability improvement of any kind
(new operator, query template, multilingual pattern, citation technique, repo-discovery
strategy, source-expansion heuristic, community-discovery method, verification protocol,
reconstruction approach, cadence/reliability mechanism, …) AND it passes the desk's standard
evidence gates, it is IMMEDIATELY added to the Search Operator Library as a permanent,
versioned asset. Every other digger MUST then adopt and ADAPT it to its own regional,
linguistic, and domain context within its NEXT session. Adaptation means TRANSLATION into the
local language + platform ecosystem, never verbatim copying: a Baidu operator from the Chinese
miner becomes a Yandex operator for the Russian miner, a Naver operator for the Korean miner,
a Gitee strategy becomes a GitHub-JP / Qiita strategy, and so on. No digger may fall behind
the capability frontier established by any other. If a digger cannot adapt a specific
improvement to its context, it LOGS the reason and the blocking condition in the library entry
itself; those logs are reviewed by the Discovery Bottleneck Detector duty each cycle for
resolution. The fleet upgrades together or not at all. This rule binds every current and
future digger from birth.

## 17. DISCOVERY COUNTERFACTUALS

Every major discovery records: "Would this have been found anyway if this search had never
run?" Estimate uniqueness and dependence on the specific operator, language, region, and
maintainer/community that surfaced it. LOW counterfactual probability = HIGHER strategic value
(genuine information advantage, not widely accessible knowledge). Recorded in the discovery's
card/log and used in source-yield learning and budget allocation.

## 18. NEGATIVE KNOWLEDGE (standing, REVERSIBLE — never a permanent exclusion)

Search areas, source classes, repositories, communities, query patterns, and discovery
strategies repeatedly explored with low validated information gain are documented in
`docs/research/negative_knowledge.md`. Their exploration priority MAY be reduced for
efficiency but they are NEVER permanently excluded. Each record stores: exploration history +
search coverage; reason for low value (no sources / poor quality / duplication / licensing /
abandoned / …); confidence the area was adequately explored; conditions justifying immediate
re-exploration; scheduled review date. Under Temporal Rediscovery, ALL records re-evaluate on
a recurring cadence (quarterly default) or SOONER on trigger evidence: new repos, APIs,
maintainers, conferences, acquisitions, ecosystem growth, citations, forks, mirrors, or
community activity. A past lack of discoveries is evidence about the PAST, never proof about
the future — every negative conclusion is provisional and fully reversible.

## 19. DISCOVERY FRONTIER ESTIMATION (standing)

Continuously estimate the frontier of the searchable information universe: coverage measured
across source classes, regions, languages, asset classes, institutions, developer ecosystems,
publication venues, and data types (extends the coverage maps + quarterly
Coverage-Completeness Audit). Search allocation weighs BOTH expected validated information
gain AND estimated frontier coverage, so heavily-explored areas never indefinitely crowd out
poorly-explored ones.

## 20. INFORMATION OPTION VALUE + INFORMATION ASYMMETRY SCORE

OPTION VALUE: potential discoveries are valued for future OPTIONALITY, not only immediate use.
Sources that unlock new research directions, enable future reconstructions, or expose
previously inaccessible ecosystems earn additional strategic value because they expand the
future search space — a small obscure dataset opening a new regional exchange ecosystem can
outrank a large high-quality dataset in an already-covered domain. ASYMMETRY SCORE: score each
source on expected informational uniqueness (language accessibility, regional concentration,
technical specialization, discoverability, indexing quality, popularity). Higher asymmetry
raises exploration PRIORITY but never substitutes for empirical validation.

## 21. INFORMATION ECOLOGY MONITOR + CANARY SEARCHES

The information ecosystem EVOLVES; the mission evolves with it. Continuously monitor
structural changes: new exchanges, repository migrations, API deprecations, licensing changes,
organization formation, acquisitions, conferences, community fragmentation, new publication
venues. Major ecosystem changes trigger TARGETED rediscovery immediately, cadence or not.
CANARIES: maintain a small representative set of canary searches spanning multiple ecosystems
(`docs/research/canary_searches.md`); unexpected changes in results, repo counts, API
behaviour, maintainer activity, publication rates, or documentation structure trigger broader
rediscovery before the next cadence. Emergence indicators watched: publication velocity,
contributor growth, repo activity, citations, forks, mirrors, community expansion, conference
appearances, ecosystem adoption.

## 22. DISCOVERY HYPOTHESIS ENGINE

The mission does not only search known categories — it continuously generates EXPLICIT
hypotheses about where valuable information might exist but has not yet been observed
(`docs/research/discovery_hypotheses.md`). Each hypothesis records rationale, expected
information value, supporting evidence, search plan, confidence, and validation outcome. Both
successful AND failed hypotheses are permanent learning records: the search process itself is
a falsifiable, self-improving research programme. Every newly validated + adopted dataset is
IMMEDIATELY queued for hypothesis generation by the Prospector, the feature/generation
pipeline, and any relevant digger — no new data axis sits idle.

## 23. WEAK SIGNAL REGISTRY

Individually weak but repeatedly observed signals — patterns, source leads, or hypotheses
below the validation threshold on their own — are RETAINED in
`docs/research/weak_signal_registry.md`, never discarded. When multiple weak signals from
INDEPENDENT discovery paths converge on the same direction, they auto-promote to combined
hypothesis generation and full adversarial validation. What is noise in isolation may be
signal in aggregation.

## 24. SEARCH REGRET ANALYSIS + INDEPENDENT REDISCOVERY

REGRET: after every cycle, estimate which searches produced unexpectedly little value, which
unexpectedly produced major discoveries, which opportunities were missed, and whether a
different allocation would probably have helped. Historical regret INFORMS future allocation
(probabilistic, never deterministic). REDISCOVERY: high-value discoveries should, whenever
practical, be independently rediscovered through UNRELATED search paths to confirm they are
genuinely discoverable rather than artifacts of a single route or community.

## 26. SCREEN-ON-DISCOVERY (principal approved 2026-07-23, binds every digger and miner)

SCREEN-ON-DISCOVERY DUTY (principal APPROVED 2026-07-23, standing law -- closes the desk's oldest leak: diggers CATALOGUED datasets and stopped, so catalog breadth ran ~8.5/10 while ingested-AND-TESTED ran ~4.5/10). DISCOVERING A DATASET IS HALF A DELIVERABLE. Every digger and every miner that surfaces a new data axis MUST, IN THE SAME RUN, carry it through a Stage-A screen and report the survivor verdict -- do not queue it, do not hand it off, do not wait for a brain cycle. THE EVIDENCE THIS IS RIGHT: 420 price-family hypotheses produced 0 survivors, while ONE new axis (kimchi premium) screened in about an hour produced IC +0.148 and momentum timing Sharpe 1.3 -- beating every price-only sleeve the desk ever rejected. The edges are in untouched axes, not the picked-clean price space.

HOW -- NON-NEGOTIABLE, because the discipline is the ONLY thing that keeps this from becoming a phantom-edge factory: (1) USE THE AUDITED HARNESS libs.research.axis_screen -- pass an aligned (signal, target) series and it runs z-score, IC, momentum/reversal Sharpe, the de-contamination (angle-20) artifact gate, residual IC, verdict, and forward-clock persistence. The artifact gate is BAKED IN: never bypass it, never hand-roll your own screen. It is what caught Coinbase-premium AND Turkey-premium as pure timing artifacts and graveyarded them. (2) MECHANISM PRIOR FIRST -- screen only axes with a STATED economic mechanism; screening everything catalogued is breadth-mining with extra steps, which the 420/0 result already refuted. (3) LOG EVERY CONSTRUCTION YOU TRY, not just the one that printed. If you test a USDT-denominated build and then an FX-denominated build, BOTH are trials and BOTH go in the record -- reporting only the winner is garden-of-forking-paths p-hacking and is the single easiest way for this duty to manufacture fake edges. (4) DECLARE TIMESTAMP ALIGNMENT for every cross-source series and flag look-ahead risk explicitly -- a daily FX close is NOT the crypto UTC close. Unstated alignment voids the screen. (5) ZERO PROMOTION AUTHORITY -- Stage A earns a pre-registered FORWARD CLOCK, never a cent; only Stage B (forward evidence + Holm slot) promotes to capital. (6) NEGATIVE SCREENS ARE FIRST-CLASS DELIVERABLES -- a failed screen is graveyarded WITH its reason. Silent drops are forbidden and 'I only report my hits' is the failure mode; negative results are free multiplicity budget and permanent knowledge.

See `docs/research/TWO_STAGE_DISCOVERY_LAW.md` (Stage A vs Stage B) and the harness `libs/research/axis_screen.py`. A dig that surfaces a new axis and does NOT report its Stage-A verdict in the same run is an INCOMPLETE dig, not a finished one.

## 27. UNIVERSAL DATA-LOOT EXTRACTION (principal approved 2026-07-23, binds every digger, EVERY source)

RELENTLESS STANDING HUNT -- this is HIGHEST-PRIORITY, because new orthogonal free data is the desk's binding constraint (new_orthogonal_data x1.6, the top breadth lever; DATA-AXIS MISSION ELEVATION makes it a first-class DIG-TO-EXHAUSTION target). Hunt it EVERYWHERE, in EVERY LANGUAGE (§1 language-blind: CJK/KR/JP/RU/AR/PT + every frontier -- value is language-independent and the best regional data hides in non-English sources), from EVERY source -- as if the next axis is the one that breaks the 0-survivor drought, because it well might be. EVERY source a digger touches -- NOT just repos -- is a LOOT CONTAINER for DATA. Repos are the primary case (§2 GitHub maximalism), but this duty binds the WHOLE source universe (§25): GitHub repos + Discussions/Issues/forks, forums/Reddit/community threads (§9), Discord/Telegram PUBLIC channels, video transcripts (every language), papers (litminer), Kaggle/HuggingFace notebooks + datasets, blogs, regulatory filings (EDGAR + non-US equivalents), exchange portals, regional-venue docs, aggregator catalogs -- wherever a digger reaches, it strips for DATA before moving on.

DISCIPLINE IS WHAT MAKES THE URGENCY PAY (non-negotiable): relentless is not FRANTIC. The desk's own evidence -- 420 breadth-mined hypotheses -> 0 survivors, and the generation-ROI harness -- proves that undisciplined breadth is a junk factory that raises the DSR wall on itself. So the hunt is WIDE but every find still passes the gates below (legitimacy, orthogonality, verify-don't-trust, screen-on-discovery, log-the-negative). Urgency means MORE SOURCES COVERED PER CYCLE and NO obscure corner skipped -- never lowered gates, never unverified data trusted, never a rate-limit ban from hammering. The relentlessness is in the BREADTH of the search, the rigor is in the GATE; both, always. Methods are harvested elsewhere; this is the DATA layer. Prioritise the niche / low-star / obscure / low-traffic (obscurity is never evidence of low value, §4 + §12; the crowded sources are already arbitraged). From ANY source, extract three classes of orthogonal DATA value: (a) NEW data-source POINTERS -- APIs, S3/archive dumps, feeds, regional venues, on-chain metrics the `data_universe_map.json` does not already list; (b) genuinely-open ORTHOGONAL datasets -- raw series the desk lacks (funding / liquidation / OI / order-flow / alt-data), NOT another slice of the price/derivative surface already picked clean; (c) ACQUISITION / RECONSTRUCTION tooling -- downloaders, scrapers, converters that turn a free raw source into a vendor-grade series with OWNED methodology (free-first protocol).

BOUNDS ON "EVERYWHERE" (hard): "every source" means every LEGITIMATE PUBLIC source only. The §13 legitimacy gate is absolute -- public + clean-license/clean-provenance data ONLY. NO closed-group or private-community scraping, NO ToS-violating extraction, NO paywalled/credentialed data, NO leaked vendor dumps. Reach is also bounded by the per-dig query/token budget (allocation adapts on validated information gain, §5, with exploration floors, §19) -- loot broadly within budget, never hammer a source into a rate-limit ban.

HOW -- NON-NEGOTIABLE, the discipline that stops this becoming a junk-hoard: (1) LEGITIMACY GATE FIRST (§13) -- use only clean-license or clean-provenance data; NEVER lift data a repo redistributes in violation of an exchange ToS or a vendor licence -- a leaked dump is a legal + provenance defect, log it and skip. (2) ORTHOGONALITY-OR-SKIP -- extract only a NEW axis vs the exhausted price/derivative surface; another BTC OHLCV set is not loot. (3) VERIFY-DON'T-TRUST -- diff every extracted source vs ground truth before any pipeline trusts it (the 2026-07-09 silent-zero-data class is the hazard); catalog to `data_universe_map.json` with an honest grade (verified-clean / needs-monitoring / unverified). (4) SCREEN-ON-DISCOVERY (§26) -- an extracted dataset with a stated economic mechanism is carried through the Stage-A `axis_screen` IN THE SAME RUN, never queued. (5) LOG THE NEGATIVE -- a repo stripped and found to hold nothing orthogonal is a logged deliverable, not a silent skip. NO REPO CONTAINS ALPHA (if it did, being public would have arbitraged it away) -- the loot is raw DATA + the METHOD to acquire it, never a ready edge. (6) DEPTH IS CO-EQUAL (§32) -- looting a source WIDE is only half: every orthogonal axis extracted is also driven DEEP in the same standing hunt (reconstructed to its archive floor, diff-verified, MAX_SURVIVORS Part 1 #1). Breadth of sources and depth of each extracted axis grow together; depth is NEVER allowed to lag the breadth this section generates -- a catalogued-but-shallow axis is an unfinished loot, exactly like a discovered-but-unscreened one (§26).

## 28. FREE-FRONTIER AXIOM (2026-07-24)

FREE-FRONTIER AXIOM (principal 2026-07-24, standing, all organs): ALWAYS assume a free alternative to any paid dataset EXISTS online and has simply not been found yet -- exchange archives, S3 buckets, academic mirrors, government portals, regional venues, GitHub repos, forgotten APIs, community lakes, vendor free tiers and samples. ALWAYS assume the free-data frontier is NOT exhausted: new sources appear daily (new repos, new archives, new listings, new regulators, new chains), so 'we already looked' is never a reason to stop -- hunt aggressively for high-ROI datasets every single session, and treat 'no free source exists' as a claim requiring EVIDENCE (a documented search that failed, graded residual_gap in the universe map), never a default. FOREIGN FRONTIER, EXPLICITLY: the hunt is NEVER English-only -- the Chinese internet alone (Gitee, CSDN, 8btc, ChainNode, Feixiaohao, university mirrors, government statistics portals), plus Korean, Japanese, Russian, Arabic, Portuguese, Turkish and Spanish communities, hosts enormous free datasets and reconstructions that never surface in English searches. Search in the NATIVE language with native operators (the Search Operator Library has per-region adaptations); a dataset's language is never a reason to skip it -- value is language-independent. The legitimacy gate (charter 13) applies unchanged in every language: clearly-licensed and public only, graded residual otherwise. PRECISION OF SCOPE: this axiom governs the SOURCE hunt, not the graveyard -- hypothesis classes killed by the gauntlet stay dead (negative knowledge is sacred); the axiom says the next ORTHOGONAL dataset is out there free, not that dead signals revive. Paid is a last resort permitted only by the evidence-gated exception AFTER the documented free hunt failed. DEPTH PARITY (§32): a newly-found free source is not DONE when catalogued -- it is reconstructed to its full archive depth and diff-verified. The frontier is pushed in BOTH axes at once: a new source found is breadth, that source mined back to its earliest real data is depth -- never breadth-only, and depth never trails.

## 29. NO-CEILING AXIOM (2026-07-24)

NO-CEILING AXIOM (principal 2026-07-24, standing, generalizes the free-frontier axiom to EVERYTHING): for EVERY dimension of this desk -- geometric growth and compounding, alpha discovery and research throughput, data depth and breadth, miner and digger potential, execution quality, cost efficiency, self-improvement, tooling, prompts, audits, this very axiom -- ALWAYS assume the current level is NOT the ceiling: a better configuration, a deeper construction, a faster clock, a cheaper path, a sharper question exists and has simply not been found yet. 'We are at max' is a claim requiring EVIDENCE -- a documented push that failed, with the measured result and an explicit lifting condition logged -- never a default, never an assumption, never fatigue wearing the mask of completion. Every organ, every cycle, every review must actively hunt the binding constraint on every dimension it touches and push it, exactly the way the principal himself relentlessly probes: assume below-potential, find what caps it, push evidence-first. ## 32. DEPTH-BREADTH PARITY (2026-07-24, standing law, binds every breadth directive)

Breadth (how many axes / sources) and depth (how far back, how granular, how completely each axis is reconstructed and verified) grow TOGETHER; depth is never allowed to lag the surface. The rule is NOT 'slow breadth to equalise' -- it is 'depth always levels UP to whatever breadth reaches': every axis breadth acquires is driven to its archive-depth ceiling (reconstructed-history backfill, MAX_SURVIVORS Part 1 #1; §30 EXHAUSTED-achievable) and diff-verified, so no axis sits shallow at ~25-40 forward days while the surface keeps widening. WHY THIS IS LAW: a shallow axis cannot validate -- it waits weeks on the forward clock, so breadth without depth is potential that never converts (the utilisation-without-conversion trap the desk already flagged). Depth collapses the clock and is the calendar-cheap survivor multiplier; letting it fall behind breadth is the single easiest way to look busy (more axes) while converting nothing. ENFORCEMENT: this law binds EVERY breadth directive (§25, §27, §28, §30) and every digger / miner / expansion prompt -- wherever breadth is pursued, depth is pursued in the same breath and to the same standard; the daily sweep flags depth lagging breadth as a defect (`max_audit.check_depth_parity`). DISCIPLINE UNCHANGED: depth is reconstructed ONLY from real archives, diff-verified against ground truth, and HELD-not-admitted when the forward overlap is too thin to verify -- depth is NEVER fabricated to clear the parity flag (that is the breadth-side volume-machine error wearing depth's clothing). BOUNDED HONESTLY: an axis whose archive is genuinely thin (e.g. cny_premium P2P) logs its measured depth ceiling and is EXEMPT -- parity means 'as deep as the archive legitimately allows', never invented depth.

## 33. MINED-TO-WIRED LAW — ZERO RESEARCH INVENTORY (2026-07-25, binds every digger and miner)

MINED INTELLIGENCE IS INVENTORY, AND UN-CONVERTED INVENTORY IS WASTE THAT DEPRECIATES. A finding catalogued and never wired has produced NEGATIVE value: it consumed a cycle, it inflates the desk's capability inventory, and it makes every later audit read the desk as richer than it is — the map-vs-territory failure, applied to the desk's own research. MINING IS NOT THE PRODUCT; CONVERSION IS. A perfect dig with zero conversions is a FAILED CYCLE and is reported as one. WHY THIS IS LAW: two consecutive cycles produced excellent primary-artifact findings (a 5.7-year archive understatement recovered from one mistranslated character; a "backfill-destroyed" claim refuted with ~88 free full-depth ground-truth days) and NOT ONE was wired, screened, or committed — the desk proved it can mine faster than it converts, which is the definition of producing debt.

(1) T+1 DISPOSITION — NO ITEM SLEEPS TWICE. Every carded find from cycle N carries EXACTLY ONE disposition by end of cycle N+1, written inline in the dig-output doc as `[§33: <disposition>]` on the item's OWN line (a blanket tag at the top of a document launders nothing). Four legal values, no fifth: `wired` (code exists AND executed AND wrote a real artifact) / `screened` (a Stage-A screen RAN; result in research_memory, --axis tagged) / `killed` (graveyard entry carrying the MECHANISM of death, never "low priority") / `deferred(YYYY-MM-DD)` (a NAMED blocker and a date). SILENCE IS A DEFECT, not a neutral state. "Interesting", "noted", "for future work", re-cataloguing, and moving an item to another inbox are NOT dispositions.

(2) ARTIFACT-ONLY CREDIT — CLAIMS ARE WORTH ZERO. Conversion is measured from artifacts on disk, never from a report, a status line, or the organ's own summary; an organ does not grade its own homework (same rule as `_converted_axes`). A `wired`/`screened` tag with no corroborating artifact is reported as UNBACKED and counts as unconverted — otherwise the cheapest way to clear a backlog is to type the word "wired", which would make the law self-defeating.

(3) ANTI-HIDING. An UNDATED deferral is ILLEGAL — it is the hiding place every rotting backlog uses. A deferral EXPIRES: on its date the item returns to the backlog. A promise with a clock, not a filing cabinet.

(4) CONVERSION PREEMPTS PRIORITY, NEVER ACQUISITION (amended 2026-07-25 by principal directive: mining must never be throttled, paused, or reduced). While any carded find owes a disposition, `scripts/mine_gate.py` recomputes the backlog at dig time and the dig spends its FIRST effort clearing it, highest tier first -- then continues mining in the SAME run. The dig is NEVER blocked, skipped, or shortened: unprocessed data is unrealized OPTION VALUE, living-web sources decay, and a suspended miner permanently loses that day's information, which is a strictly worse failure than temporary inventory. Extraction scales UP to meet acquisition; acquisition is never cut down to meet extraction. Mining growth and exhaustion remain unbounded and are themselves maximised -- §33 governs only what happens to what has ALREADY been mined. Pressure comes from defects and escalation (`mine-conversion-*`), never from a stop.

(5) COMMIT OR IT DID NOT HAPPEN. Dig output not committed AND pushed by end of cycle DID NOT HAPPEN and earns zero credit — git is the institutional memory, VPS disk is not; an uncommitted finding is one disk failure from never having existed, and an audit reading only the repo cannot see it at all. Enforced by `max_audit.check_dig_uncommitted`.

(6) CONVERSION PRIORITY — HIGHEST ROI FIRST. Work the backlog in order, never starting tier N+1 while tier N has items: TIER 1 DEFECT-CLOSERS (anything making a permanently-firing gate satisfiable or unblocking a standing blocker — worth more than new capability because it stops ongoing bleed); TIER 2 MECHANISM-LEVEL PRIORS on axes ALREADY INGESTED (pure §31 mechanism-first work on data already paid for); TIER 3 new data surfaces with a live collector path; TIER 4 operators, lexicons, diaspora leads.

(7) DEPTH PARITY APPLIES TO CONVERSION (§32). A token wiring is NOT a conversion. Every converted item reaches the depth of the DEEPEST converted item in its class — full history pulled not sampled, the fence actually RUN not merely referenced, the screen run on the full available window not a convenient slice. Conversion depth grows at least as fast as conversion breadth and NEVER lags it; breadth of conversion rising while depth is flat is a §32 defect. Do not slow breadth to achieve parity — RAISE DEPTH TO MEET IT.

(8) FIRST-PASS GRADES ARE NOT EVIDENCE. Measured 2026-07-25: 4 of 5 prior claims on a re-verified source card were REFUTED. First-pass catalogue grades are UNVALIDATED GUESSES; treat every needs-monitoring / UNVERIFIED grade as unreliable until re-verified against a PRIMARY artifact. Log the running first-pass error rate each cycle; while it exceeds 25%, RE-VERIFICATION OUTRANKS NEW CATALOGUING and the cycle budget shifts accordingly without asking.

(10) QUALITY — A DISPOSITION IS NOT AUTOMATICALLY A CONVERSION. `killed` is artifact-checked against the GRAVEYARD exactly as `wired`/`screened` are checked against collector output: to kill an item you must write its graveyard entry carrying the mechanism of death. This closes the cheap exit BY CONSTRUCTION — mass-killing the backlog now costs strictly MORE than converting it, instead of being the fastest legal way to resume mining. The wired:screened:killed ratio is reported every sweep; a kill-share above the bar (`mine_kill_share_bar`, tighten-only) is its own defect (`mine-conversion-killspike`).

(11) VALUE-WEIGHTED BACKLOG. Every carded find carries a TIER (inferred, or forced with `tier:N` in the tag) and the backlog is priced by tier weight (T1=8, T2=4, T3=2, T4=1), so the gate cannot be cleared by converting only the cheap tail. Completing lower-tier work while a Tier-1 defect-closer still owes is a PRIORITY INVERSION defect (`mine-conversion-inversion`) — clause 6's order is enforced, not merely stated.

(12) FLOW, NOT ONLY STOCK. A backlog count says whether inventory exists; only LATENCY says whether the desk is improving. Every sweep appends a snapshot to `data/mine_conversion_log.jsonl`; find→conversion latency and the age of the oldest owing item are derived from consecutive snapshots (never from a timestamp a human must remember to write). An item owing longer than `mine_stale_owing_days` is a rotting-inventory defect; a worsening latency TREND is caught before it becomes a regression.

(13) THE RATCHET — SELF-IMPROVING BY CONSTRUCTION. The standard is the desk's OWN BEST-EVER performance, persisted in `data/mine_conversion_ratchet.json`: every record (faster median latency OR higher conversion rate) tightens the bar permanently, and a worse cycle NEVER loosens it — it produces a `mine-flow-regression` defect instead. Regression is measured against the RECORD, never against last cycle, so a slow drift downhill cannot read as "fine" at every step. There is no "good enough" state; there is better-than-our-best, or a defect. This is the NO-CEILING AXIOM made mechanical for conversion.

(14) THE CLOSED LOOP — CONVERSION STEERS GENERATION. Per-source conversion rates and latencies are published every sweep to `data/mine_generation_priors.json` (favour / starve lists + full class table). EVERY DIGGER MUST READ IT AND REWEIGHT: a class converting at 60% earns more of the next cycle than one converting at 5%, and that reweighting happens from MEASURED OUTCOMES, not enthusiasm. Thin classes (<3 observations) are omitted rather than shown at a noisy rate. The loop is itself verified — if new finds keep arriving from classes measured below a 25% conversion rate, `mine-feedback-ignored` fires, because a prior nothing acts on is the same failure as a law with no monitor. A gate that only blocks is a fence; a gate that reweights is a control system, and only the second one is maximum utilisation.

(15) THE GATE IS DERIVED, NOT A FLAG. A gate that is a file is a gate `rm` defeats: deleting `data/mining_suspended` would have restored mining without converting anything, making the law advisory again. Every digger shell now RUNS `scripts/mine_gate.py`, which RECOMPUTES the backlog from the docs at dig time. There is no state to delete; the only way to open the gate is to actually dispose of the findings, and the only way to disable it is to edit tracked code, which appears in a diff and in review. The gate FAILS OPEN, loudly and deliberately: a day of over-mining is cheap and recoverable, while a bug that silently freezes the desk's entire research intake for a week is a self-inflicted outage. That asymmetry is not a loophole because it is watched — `max_audit.check_mine_gate` fires on a missing gate, on any digger shell that does not invoke it, and on a gate that raised and failed open, so an ungated desk surfaces within one sweep instead of hiding behind either outcome.

(16) EXACT ARTIFACTS OVER NAME MATCHING. The strong form of a terminal disposition names its evidence: `[§33: wired -> data/upbit_1m.jsonl]` (or `@ path`). The named path must EXIST and be NON-EMPTY, so a rename, a deletion, or an empty stub all fail loudly, and a claimed path that isn't there can never be laundered by a coincidental name hit. Fuzzy name matching remains only for cards written before this syntax; it is genuinely weaker (a rename silently breaks credit, a coincidence silently grants it), so every sweep COUNTS the claims still relying on it (`mine-conversion-fuzzy`) — not a backlog defect, but a standard the desk ratchets up without needing a flag day.

(17) NO ERASABLE OBLIGATIONS — the gate-file lesson, generalised. Every §33 bypass found by attacking the law adversarially was the same shape: state that could be DELETED or FORGED. Enforcement is only as strong as its weakest erasable surface, so each is closed by deriving it or by putting it where deletion is VISIBLE. (a) DELETING THE CARD DOES NOT DELETE THE OBLIGATION — the snapshot ledger remembers, and a find that owed a disposition in the last snapshot and has since disappeared from the docs fires `mine-item-vanished` by name, immediately. An editor is no longer the cheapest way to clear a backlog. (b) AN ARTIFACT MUST POSTDATE ITS FIND — exact paths were not enough, because any pre-existing non-empty file in the repo was a valid receipt for any claim (`-> pyproject.toml` was credited). The named artifact's mtime must be later than the find's first appearance in the ledger; doing the actual work satisfies this for free, including a graveyard entry, which touches graveyard.md. (c) THE RATCHET LIVES IN GIT — `docs/research/conversion_record.json`, TRACKED, not under gitignored `data/*` where `rm` produced a fresh and easier record. A reset now shows in `git status`, in the diff, and in check_dig_uncommitted. The record additionally carries the ledger's high-water marks (snapshot count only grows; earliest timestamp only moves backward), so truncating or rewriting the evidence base fires `mine-ledger-truncated` instead of silently resetting latency, priors, and the bar together. (d) THE LAW'S SCOPE IS ITSELF AUDITED — §33 reads a fixed list of docs, and a digger writing its cards anywhere else would evade every check in the family WITHOUT touching tracked code, the one bypass that leaves no diff. Any `docs/research/*.md` carrying numbered cards must be either in the scanned set or in the explicit exclusion list with a stated reason (`mine-scope-unmonitored`). Consciously excluded is fine; quietly unmonitored is not — nothing may fall between the two by omission. THE FLOOR: after this, the only remaining way to defeat §33 is to edit tracked code — which appears in a diff and in review, and is the correct floor for any law a system enforces on itself.

(18) THE LAW IS HELD TO ITS OWN STANDARD. Clauses 1-17 pressure the DESK; none of them asks whether §33's own machinery earns its place, and a law exempt from the evidence standard it enforces is precisely the hypocrisy the NO-CEILING AXIOM forbids ("we are at max" is a claim requiring evidence, never a default). Two self-audits close that. (a) TIER WEIGHTS ARE VALIDATED, NOT ASSERTED — T1=8..T4=1 claims Tier-1 finds are the high-ROI ones; if measured outcomes show Tier-1 items converting less often than Tier-4, the weighting is not merely useless but actively steering effort toward work that never finishes, and `mine-tier-miscalibrated` demands it be corrected. It deliberately does NOT silently re-learn the mapping from its own outcomes — a heuristic quietly rewritten by the data it produced is unauditable — it DETECTS that the mapping is wrong and requires a human-legible fix. (b) THE LAW MUST SHOW IT WORKED — the first third of the conversion ledger is compared against the last third, and if the rate has not risen and latency has not fallen after enough cycles, `mine-law-ineffective` fires and §33 states in those words that it is ceremony with good telemetry. HONEST LIMIT, recorded rather than buried: there is no pre-§33 baseline and no control group, so this is a TREND and not a counterfactual — it cannot prove §33 caused an improvement, only that one did or did not occur while it was in force. That is still strictly better than the alternative the desk would otherwise use, which is assuming a law works because it was written carefully.

(9) THE STANDING TEST. Before ending any cycle, answer in writing: "Which artifact on disk is different because of what was mined?" If the honest answer is "none", the cycle FAILED — say so in those words. A cycle that produced only reports produced nothing.

## 34. MINING NEVER REGRESSES — THE TWO-DIRECTIONAL RATCHET (2026-07-25, principal, strict)

§33 ratchets CONVERSION upward. This clause ratchets MINING upward too, and forbids the desk from
ever satisfying one at the expense of the other.

(1) THE LOOPHOLE THIS CLOSES. The cheapest way to raise a conversion RATE is to shrink the
denominator — mine less. A desk under conversion pressure will find that move on its own, and it
looks like an improvement in every metric while destroying the thing that cannot be recovered.
Un-mined information is not deferred; living-web threads decay, forums close, archives vanish, and
a source not dug today may not exist to dig later. Acquisition foregone is permanent.

(2) THE LAW. Mining volume, breadth and depth may never fall. Conversion pressure NEVER reduces,
pauses, throttles, shortens or narrows a dig — it reorders that dig's PRIORITY (convert first,
highest tier first) and the dig then continues mining and exhausting new ground in the SAME run.
Extraction scales UP to meet acquisition; acquisition is NEVER cut down to meet extraction. If the
desk cannot convert what it mines, the answer is always a bigger engine, never a smaller intake.

(3) MECHANICAL, NOT ASPIRATIONAL. `max_audit.check_mining_nonregression` ratchets carded-find
volume against the desk's own best-ever (record in `docs/research/mining_record.json`, tracked in
git); a materially lower cycle fires `mining-regression`. `max_audit.check_no_mining_throttle`
re-verifies every surface a throttle could return through — the gate must exit 0, no digger shell
may carry a blocking early-exit, and the verdict text may not tell a dig to stop cataloguing
(a throttle through LANGUAGE is still a throttle, since that string enters the dig prompt).

(4) BOTH HALVES ARE MAXED, NEITHER TRADED. The objective is maximum information surface area
MULTIPLIED BY maximum extraction efficiency. A rise in either that is bought with a fall in the
other is a REGRESSION, reported as one, regardless of how the headline rate reads.


## 39. CAPACITY-BOUND EDGE PRIMACY — HUNT WHAT IS TOO SMALL FOR FUNDS (2026-07-26, principal)

A ~$50k book has exactly ONE structural advantage over every fund on earth: it can profitably take trades that are too small to be worth anyone else's time. `PROSPECTOR_SPEC` already names this — "capacity-bound edges the fund ABANDONED for being too small… precisely this desk's one structural advantage" — and until 2026-07-26 the desk's own survival gate CONTRADICTED it: `_MIN_CAPACITY_USD = 1.0e5` hard-rejected any candidate that could not absorb $100,000, whatever its DSR, PBO or Sharpe. A perfect $20k-capacity listing dislocation failed on `capacity` alone. The niche the spec called the desk's advantage was unreachable by construction.

(1) CAPACITY IS A RATIO, NOT A DOLLAR FIGURE. The gate's real job is to stop the desk being a large share of its OWN edge's capacity — impact, not size. That is a ratio to deployed equity and it protects a $5k book and a $5M book identically: `capacity_usd >= max(abs_floor, headroom_mult × deployed_equity)`. Both bounds live in the ThresholdBook, bounded and evidence-adjustable. The absolute floor is deliberately FREE rather than tighten-only, because the old fixed floor was itself the defect — the desk must be able to move it DOWN as it deliberately hunts smaller.

(2) PERMISSION IS NOT PURSUIT. Removing the block is necessary and NOT sufficient: a desk merely allowed to hunt small will still default to fund-shaped ideas, because that is what the literature is written about and what the models have read. So the CAPACITY DISTRIBUTION of screened candidates is measured every sweep (`max_audit.check_capacity_hunt`). If EITHER band — the range this book can exploit, or the larger edges that will succeed them — falls below a quarter of the fillable funnel, that is a DEFECT: one whole class of alpha is going unhunted, and the objective is the maximum NUMBER of simultaneous uncorrelated alphas, not a preferred size of alpha. See (5)(c) below for why the check is symmetric rather than a niche floor.

(3) THE NAMED GROUND. Day-1 perp listing funding spikes (one-sided spec flow, no arb capital yet — the `run_listing_watch` clock already runs for this), thin-pair cross-venue funding divergence, low-OI tails of the perp universe, delisting forced-unwind dislocations. What they share is that they pay BECAUSE they are too small to interest anyone with money, and they decay as the desk grows into them. That decay is DEFINITIONAL, not a risk to be mitigated: the sequence is edge → size → next edge, which is why breadth keeps earning its cost even when depth is what converts.

(4) THE HONEST TRADE, RECORDED. Triple-digit returns and the current ruin discipline are not simultaneously available. Hunting smaller raises the ceiling for free and touches no rail. Loosening the rails also raises it, and buys the return with ruin probability. The first is doctrine; the second is a principal decision that must be made deliberately, never drifted into.

(5) PARITY, NOT PERMISSION — AND ONE SOURCE OF TRUTH (2026-07-26, second pass). Clauses (1)-(2)
removed a categorical EXCLUSION and measured the funnel. They did not deliver PARITY, and an audit
of the scoring math showed why: the $100k floor was never one number in one place, it was FIVE
copies of a policy that disagreed with each other. Fixing the survival gate left four intact —
`discovery.objective` gave a $1m idea a 1.9x rank advantage over a $50k one, `alpha_economics` a
3.2x EV advantage, `discovery.factory` still hard-failed acceptance below a flat $1e5, and
`capacity_intelligence` scored scalability against a $10m reference so a niche edge scored ~0.5 out
of 100. A candidate could therefore pass the fixed gate and still lose every ranking to a
fund-shaped idea it beat on every dimension that actually pays. Being ALLOWED into the niche while
being SCORED out of it is the same exclusion moved one layer down, where it is harder to see.

The law has three parts, all mechanical:

  (a) CAPACITY SCORES AS SUFFICIENCY, NEVER AS MAGNITUDE, AND NEVER TILTED EITHER WAY.
  `libs/research/capacity_policy.py` is the single definition and every scorer imports it. The
  score ramps to the headroom requirement, then goes FLAT — above sufficiency, size stops being a
  tiebreaker and the edge is judged on Sharpe, orthogonality and persistence like everything else.
  That flat region IS the parity. Capacity you cannot fill is not an advantage you own; rewarding
  it is preferring an option you cannot exercise.

  A first pass then discounted fund-scale capacity as a crowding prior. THE PRINCIPAL STRUCK IT
  (2026-07-26) and was right twice over. First, the objective is the MAXIMUM NUMBER OF SIMULTANEOUS
  UNCORRELATED ALPHAS — that is what compounds — so a sleeve declined for its SIZE is geometric
  growth foregone, and being picky about the shape of an edge is not risk management. Second, it
  DOUBLE-COUNTED: crowding is already priced by the `crowded_known` prior and re-tested by DSR, PBO
  and persistence, so charging it again in the capacity term punished large edges twice for one
  fact. The score is now flat for everything fillable, full stop. The mechanism survives, defaulted
  to neutral and bounded in the ThresholdBook, so MEASURED decay-versus-capacity evidence could
  reintroduce a discount later — evidence may move it, preference may not.

  (b) NO EDGE IS FILLED WITH THE WHOLE BOOK. Capacity is judged against the equity ONE SLEEVE
  receives, not against the desk total. Comparing every candidate to the full book silently assumes
  an all-in single-strategy desk and inflates the requirement by the sleeve count — the flat-floor
  bug in miniature. The divisor is explicit (`DEFAULT_SLEEVES`), never implied.

  (c) BOTH BANDS ARE HUNTED, BOTH ARE RUN, AND THE CHECK IS SYMMETRIC. `check_capacity_hunt` fires
  when EITHER band falls below a quarter of the fillable funnel. The first version enforced a niche
  FLOOR, which is the same bias pointed the other way: it would have sat silent while the desk
  hunted nothing but tiny edges. Hunting only small costs twice — the large alphas that would have
  run ALONGSIDE the small ones are never found, and there is no successor inventory for the day the
  book outgrows what is running. Nothing is ever declined to make room for something smaller.
  Separately, candidates that cannot absorb even one sleeve are their own defect — small is the
  advantage, too small to fill is not, and the two must never be scored as the same thing.

  (c2) THE ONLY REASON A SLEEVE EVER STOPS IS ARITHMETIC. An edge is deployed while it is fillable
  and retired when the book genuinely passes its capacity — never because something bigger came
  along, and never because it was small. `outgrown_at` gives every edge the exact book size it dies
  at and `growth_runway` gives the multiple of today's equity it survives, so the expiry is a date
  rather than a surprise, and `check_capacity_runway` fires both when an edge has ALREADY been
  outgrown and when nothing on the shortlist survives a doubling. That second one is the real
  discipline: the replacement must be in the pipeline BEFORE the expiry arrives, which means
  hunting the larger band concurrently rather than afterwards.

  (c3) THE RATIO IS EVALUATED AGAINST THE LIVE BOOK, NOT A LITERAL. `live_book_usd` and
  `live_sleeves` read the hash-chained NAV attestation, so the requirement rises by itself as
  equity compounds and the desk outgrows small edges automatically. "Capacity is a ratio" and "the
  ratio is measured against a hardcoded $50k" are the same bug one step apart. A missing, stale
  (>7d) or corrupt ledger falls back to the CONSTANT and never to zero — an unreadable file must
  never be the loosest possible gate, which is exactly what the old `deployed_equity_usd = 0.0`
  default silently was. The live sleeve count is floored at the planned count, because running one
  sleeve today means the desk has not diversified YET, not that one edge may swallow the book.

  (d) THE GUARD IS STRUCTURAL, NOT NUMERIC. `check_capacity_single_source` enumerates every scorer
  that judges capacity and fails if one does not import the shared policy, or carries a
  fund-shaped dollar literal on a capacity line. Checking the SHAPE OF THE DEPENDENCY rather than
  the value of a threshold is what makes the guard survive somebody legitimately re-tuning the
  threshold. Five copies is the failure mode; one import is the invariant.

(6) EVENT-SHAPED EDGES NEED AN EVENT-SHAPED GATE. Every promotion gate the desk owns scores a
continuous daily return series. That is the right shape for carry and trend, and the WRONG shape
for the edges (3) names: a day-1 listing funding spike is a few hours, a few times a week, and it
is over. Thirty such events are thirty observations, but strung into a daily series they are ~2
non-zero days in 30 flat ones and every continuous statistic reads that as noise. The desk could
therefore COLLECT listing data forever and never be able to PROMOTE what it found — acquired but
not convertible, which is a §33 failure wearing a statistics costume.

`libs/validation/event_study.py` is that missing path, and the unit of evidence is the EVENT. It
is not a weaker bar, it is a denser one: 30 events are 30 largely-independent draws where 40 daily
returns are 40 autocorrelated ones, so the clock shortens because the EVIDENCE is denser, not
because the standard moved. It carries the same discipline as everything else — a Brown-Warner
cross-sectional t against a Holm bar deflated by the cohort actually screened, a bootstrap CI that
must ALSO exclude zero (a parametric t alone is defeatable by crypto's fat tails), overlap measured
and effective-N discounted by it exactly as §31 discounts trial counts, and a hard refusal below
20 observations. A constant return series is refused as a DATA DEFECT rather than scored, because
`std == 0` never fires in floating point and the t-stat would otherwise explode past every bar.

The hypothesis is PRE-REGISTERED in code (`libs/research/listing_events.py`): direction, holding
window and funding threshold are module constants, not arguments, because arguments get swept and
the best result reported — and then the multiplicity correction is a lie, since the trials are
invisible. A second window is a NEW hypothesis and must raise `VARIANTS_TRIED` so the bar rises
with it. A PASS is EVIDENCE and nothing more; Gate-0 and the ordinary promotion path still stand
between it and any allocation, and real capital is never allocated automatically.

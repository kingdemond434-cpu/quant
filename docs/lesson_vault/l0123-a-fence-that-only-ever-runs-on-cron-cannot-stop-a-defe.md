# L0123

A fence that only ever runs on cron cannot stop a defect its own desk authors: the object is committed and pushed hours before the sweep, so 'why does this exist?' always reaches a session that must answer it from cold. When a defect key RECURS on new instances, check WHICH BOUNDARY the check runs at before improving the check -- the detector is usually already right.

## Evidence

scripts/max_audit.py appears in neither run_law_gate.py _LAW_FENCES, .git/hooks/pre-push, nor .github/workflows/ci.yml; four birth-property keys recurred 6x/4x/3x/2x, and commit 9f3e2fcf is literally 'fix artifact-ungoverned that MY OWN commit introduced'. Fixed by scripts/check_birth_properties.py in _LAW_FENCES, 2026-08-12.

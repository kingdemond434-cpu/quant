# L0096

Establish a source's legitimacy posture with a UA matrix against a REAL CONTENT PATH, never from robots.txt alone. A CDN can enforce a policy robots.txt does not state, and a blocked ground is byte-identical to an exhausted one in any fetch path that treats a non-200 as no-content -- so the seat records 'this ground is thin' when the truth is 'we are blocked'.

## Evidence

2026-08-12: note.com + zenn.dev serve 403 to ClaudeBot/GPTBot/CCBot/Bytespider while Googlebot, curl/8.0 and SomeRandomBot/1.0 get 200, and NEITHER robots.txt names any of them. Closed 116 of the JP seat's 187-entry mapped corpus (62%). Prior JP runs 08-01 and 08-04 read note.com bodies fine, dating the rollout. docs/research/search_operator_library.md OP-052

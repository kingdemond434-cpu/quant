# L0113

Run a hypothesis's own pre-registered falsifier BEFORE building what it proposes, and use survival analysis for any queue-latency question -- a completed-only mean silently drops exactly the never-converting rows the hypothesis is about.

## Evidence

R0345 pre-registered 'measure disposition latency for compound vs atomic rows' on 2026-08-01 and sat open 10.9d while its build stayed queued; running it took one script and REFUTED it (compound KM-median 6.07d vs atomic 5.04d, log-rank p=0.9289, and compound rows are only 29/486 = 6% of the ledger, too few to explain a 200-row backlog at any effect size).

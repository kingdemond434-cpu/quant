# L0348

WHEN A LANE HAS NEVER ONCE SUCCEEDED, SUSPECT THE CONTRACT BETWEEN STAGES, NOT THE SIGNALS. Three independent shape faults each made forex unexecutable on their own: families cannot emit on the last bar of the frame they are handed (their loop is range(n, len(d)-1), a backtest convention), so filtering signals to closed.index[-1] matched nothing; the terminal accepts a 29-character order comment and the gateway truncated to the documented 31, so every order was refused at the API boundary; and rows carrying no side defaulted LONG while the family chose direction per signal, so a BUY was sent with a SELL's bracket. Each reported a plausible, misleading reason -- 'no signal on this bar', 'Invalid comment argument', 'Invalid stops'.

## Evidence

2026-09-15: zero forex family orders had EVER filled. Given 'closed', 0 of 32 sleeves emitted on the last closed bar; given the frame WITH the forming bar, 4 did on the same tick. order_check across comment lengths 0..33 returned retcode 0 to 29 and refused from 30. After all three: CHFNOK 0.01 SELL and USDCHF 0.02 SELL filled with retcode 10009.

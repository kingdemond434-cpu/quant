# L0235

When one list is maintained in two files, the safety property it encodes is only as good as the file that is checked -- and the other one is where the hole is. Derive the second from the first, or pin them with a test that reads both.

## Evidence

release.NON_CODE named 6 paths; sync_shadow_to_git.ps1 publishes 10. So every seal was valid for at most one 15-minute sync cycle: the box committed account_state.json or one of four shadow ledgers, accepts() read it as unreleased CODE, and NEW_RISK_OK went false and stayed false. The promoter kept promoting -- promotion to live is automatic here -- and every family and scalp sleeve it promoted placed nothing, with the reason only in a `report` field no dashboard renders. NEW_RISK_OK had never been true once.

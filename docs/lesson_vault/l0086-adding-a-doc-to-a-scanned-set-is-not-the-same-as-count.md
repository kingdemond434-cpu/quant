# L0086

Adding a doc to a scanned set is NOT the same as counting it. Whenever you put a path in scope, immediately assert the parser returns a NON-ZERO count from it -- a listed path that yields nothing is indistinguishable from a path checked and found clean.

## Evidence

2026-08-06: 3 of 4 _DIG_DOCS parsed to ZERO cards (feed_inbox 27 headings, discovery_hypotheses 11, literature_coverage 38) because _ITEM_RE wants '### N.' and none writes it. A ledger row had already recorded feed_inbox as 'now a measured, fenced number' -- true in SCOPE, false in EFFECT -- so §33 measured ONE doc and published it as the desk's whole mining surface for weeks. Fixed by check_mine_scope_vacuous; an EMPTY doc must still read clean or the fence teaches the desk to keep a backlog.

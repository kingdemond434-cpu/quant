# L0183

A 2xx and a healthy byte count measure a RESPONSE, never content. Before carding a source as live, strip the tags and count the tokens you actually came for -- a client-rendered page returns a full-sized shell forever, and 'the feed is already arriving' is the most expensive wrong premise on a repair queue because it ranks the work first.

## Evidence

2026-08-26: so.eastmoney.com returned 200 with 12,792 bytes, which I carded as the cheapest fix on the board. Stripped: 4,763 chars of page furniture and footer CSS, ZERO occurrences of any keyword including the term the URL searched for. Same shape as fxblue's Next.js SPA (/users 404, data client-rendered). GAP_REGISTER row 140 corrected in 2ca933f2.

# L0273

A self-tuning loop encodes a DIRECTION, and the direction is not the same for every thing it tunes. `missed_growth` walks a rail that costs growth toward looseness, and it only knew how to walk a multiplier DOWN -- correct for a shrink, backwards for a CAP, where looser means MORE room. So the family and sleeve caps could not be made tunable at all: joining the loop would have TIGHTENED them every time they proved expensive. Give the rail a `weaken_dir` and default it to the existing behaviour, so nothing that already worked moves.

## Evidence

family_cap and sleeve_share_cap were binary rails producing review tasks; hazard_shrink and position_inertia had been walking for days

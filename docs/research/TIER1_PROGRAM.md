Status vocabulary: EXISTS-LIT = code runs on a named clock and its artifact has a consumer; EXISTS-DARK = code exists, no clock or no consumer; PARTIAL = part exists (gap named); MISSING = nothing; LANDED = built in this programme, with commit.

> **What LANDED does not mean.** LANDED means the code exists in THIS REPOSITORY, on a named clock, with an artifact and a consumer. It does NOT mean the artifact has ever been produced on the trading box, and it does not mean the behaviour has been observed with money at risk. That distinction is what the five acceptance_properties measure, and they are measured from artifacts rather than asserted: an absent artifact reads UNMEASURED, never MET. Read the census as build coverage and the acceptance properties as operational proof. They are different questions and the second is the one that decides whether the desk works.

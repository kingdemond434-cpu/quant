## Adjudication

Proposal A's own strongest item was not the liveness triple; it was the generalisation it buried
under "New, not from the sweeps": *"Publish `n_scanned` on every fence, universally — the common
root is that a CLEAN/OK verdict is printed without its denominator."* That is the same defect as
all three liveness bugs, one level up, and it subsumes them. **The liveness triple is three
instances; the denominator is the class.** Built the class.

### Verified before writing a line

- `libs/ops/fence_exit.py` **already existed** (R0237/L1.28a) and is wired into 8 fences. It fixes
  the map from *status* to *exit code*. It **cannot** see this defect: `check_exploration` uses it
  and still returns OK with `n_organs: 0`, because the status is honestly `OK` and the denominator
  is the lie. Extended it rather than writing a rival — a `scanned=` kwarg at the exit site, the
  only place that holds both halves.
- **The law was already written.** L1.53(4), 2026-08-05: *"whenever a gauge can be improved by
  doing less of the thing it exists to encourage, its denominator is a first-class measurement and
  is fenced separately."* Written for the conversion ratio, fenced for the conversion ratio,
  generalised in its own text to "every ratio the desk reports", and never carried to a fence's own
  verdict. So this build is **the missing instrument for an existing duty**, not a new duty — the
  L1.36 family failure shape (per-law green, principle unreached). A duty with no instrument is a
  wish (L1.46).

### The measurement that justified the scope

Two independent `Explore` sweeps read all 40 fences by hand:

| finding | count |
|---|---|
| fences that **pass vacuously** (empty scan set → passing status → exit 0) | **18 / 40** |
| fences publishing `len(<hardcoded module-level literal>)` as a denominator | **10** |
| fences publishing a **measured** count of what the run examined | **3** |

The constant-denominator half is the nastier one: `n_organs`, `n_fences`, `n_governed`,
`n_criteria` all render as measurements and **cannot fall when the thing they count disappears**,
because they never counted it. The one event they exist to reveal is the one event they
structurally cannot show.

Design decisions worth keeping:

- **Scope is discovered, never enumerated.** `governed_fences()` globs `scripts/check_*.py`. A
  meta-fence about hardcoded denominators that carried a hardcoded list of its own scope would be
  the defect it exists to detect.
- **The refusal never depends on telemetry.** Vacuity is computed from the arguments in hand;
  the registry write is best-effort inside a `try`. The first draft computed vacuity *inside* the
  try block, so an unwritable `data/` would have silently restored every vacuous pass. There is a
  test pinning this (`test_refusal_does_not_depend_on_the_registry_being_writable`).
- **PARTIAL exits 0.** Coverage is a ratchet (L1.0) whose gap is the work queue. A fence red from
  day one gets switched off (L1.43) — which is how the fix becomes the next outage.
- **Subject to its own law.** `check_denominators` declares `scanned=n_fences`.

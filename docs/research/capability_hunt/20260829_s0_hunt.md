## Two defects this build's own first runs produced — both fixed, both now regression tests

1. **A fixed `MIN_BARS_PER_DAY = 20` silently dropped all 74 US share CFDs.** It is a 24-hour-FX
   threshold; a 6.5-hour cash session can never carry 20 bars. Their spread columns are 96%+
   non-zero and perfectly usable, and the artifact reported them as "no usable spread column" and
   read as successfully built — 123 symbols where 196 were available. This is the anti-hardcode
   law (LAWS §1) and WS-005 in one defect. Replaced by a per-symbol session length measured from
   the symbol's own tape (`max(mode, p90)` of bars/day — the median fails because on USDZAR and
   Accenture the splice is the *majority*), with no asset-class list anywhere. Exclusion evidence
   is now published per symbol as `splice_tickvol_ratio` (USDZAR 18.4×, EURZAR 14.8×, 3M 0.7×)
   so the exclusion is auditable rather than asserted.

2. **The fence's first version compared against the surface's *unconditional* hour cell and
   reported DISPERSED over a sleeve already measured at 2.5×.** A family does not trade every
   day: `overnight_gap_decay` fires only when the gap exceeds 0.75 ATR, and the book on exactly
   those mornings is wider. USDZAR hour 01 costs 1,496 pts across all days and 2,028 pts on the
   days this sleeve fills — so the unconditional cell reads 1.85×, under tolerance, silent.
   **Selection is part of the cost.** The fence now measures the actual fill bars and publishes
   the unconditional hour cell beside them so the selection effect stays visible.

Mutation-tested: restoring the fixed-20 threshold fails
`test_short_session_symbol_is_profiled_not_silently_dropped`; removing the `spread_pts` hour path
fails `test_costs_from_symbol_charges_the_hour_when_given_one`.

### The units, checked against something the desk does not control

Mode 1 (POINTS) resolves to `swap_points × tick_value` — exact, because `point == 10**-digits`
was verified equal to `tick_size` on **all 248** symbols, so the ratio is 1 rather than assumed.
The result was then checked from an independent direction: **EURUSD long computes to −5.538
account currency per lot per night, which annualises to −1.99%/yr — the EUR-minus-USD policy
differential to two significant figures.**

Mode 5 (INTEREST_CURRENT) is an annual percent of notional and needs a price and a day count.
`DAY_COUNT` is a broker convention this desk has not read, so it is **declared**, published in the
artifact, and emitted at both 360 and 365 so a consumer sees the band. 46 symbols have no price
series here and are `UNMEASURED` with the blocker named — never zero.

### A defect this module committed against itself, and the fix

The first run reported **USDJPY** — on a live forward clock, rate resolving cleanly to +3.843 —
as `UNMEASURED`, because `median_spread_pts` is 0.0 for it. Two different facts had been collapsed
into one label: *the rate is unknown* and *the rate is known but there is no spread basis to scale
it against*. That is the producer/consumer verdict collapse this desk keeps paying for, reproduced
inside the module built to end it. `UNCLASSIFIED` is now its own state, and `swap_per_lot()` keys
on the **value**, not the label — otherwise it would refuse a rate the desk actually holds. Two
tests pin both halves.

## Defects found and FIXED in this run (not notified — repaired)

1. **`swap_table_miner.py` had never been importable.** `field(default_factory=dict)` with only
   `dataclass` imported → `NameError` at class-body evaluation. Zero callers, so no test and no
   grep could see it; only an import can. Fixed and verified importing. **Cost:** the one module
   that would have detected a swap transition never ran, ever.
2. **The desk's only written swap-unit convention was wrong in both halves.**
   `libs/research/perishability.py` said *"in mode 0 (POINTS) ... in any other mode it is already
   currency"*. Mode 0 is DISABLED, mode 1 is POINTS, and mode 5 is an annual percent — so
   "already currency" was wrong on **55% of the universe**, as a **dimension** error, always in
   the direction that makes a candidate look cheaper. Corrected against the tape.
3. **`financing.TRIPLE_SWAP_WEEKDAY` asserted Wednesday universally**; the broker says Friday on
   150 of 248. `rollover_nights(triple_weekday=...)` always accepted the per-symbol value and
   nothing ever supplied one — `carry_state.triple_weekday_for()` now does, including the silent
   MT5(SUNDAY=0)→Python(MONDAY=0) off-by-one.
4. **Three severances in twelve lines of `edge_search.py`.** It globbed `*.json*` while the
   recorder writes `.parquet`; it read `recorded_at`/`at` while the recorder stamps `observed_at`;
   and `swap_diff` was a raw `swap_long − swap_short` mixing points and annual percent, with
   absent fields defaulting to **0**. Repairing the first two alone would have switched a
   mis-united conditioner ON for the first time, so the unit resolution was part of the repair.
5. **`family_carry`'s magnitude gate compared a raw broker numeral to `min_edge_bp_per_day=0.5`**
   — three dimensions against one constant. In practice vacuous: AUDHUF's raw differential is
   1,580 and USDTRY's 11,364 against a bar of 0.5, so any symbol with enough decimal places
   passed unconditionally, and the **side** was chosen by comparing numerals whose scale is the
   broker's digit count. Now resolves the unit first and stands aside when it cannot — strictly
   fewer signals, never a new one.

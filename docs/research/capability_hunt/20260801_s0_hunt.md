**Refuted, and replaced with a sharper fact.** The proposal claimed ~50% of depth polls are
"silently lost, swallowed by a bare `except: pass`". Measured, the gap distribution has
**p05 = 7.8 s with nothing near the configured 5.0 s** — an exception-drop pattern would be bimodal
at multiples of the period, and it is not. The poll loop simply **cannot finish inside its own
period**, so `time.sleep(max(0.0, ...))` sleeps zero every cycle. The mechanism is cycle stretch,
not exception loss, and the fix is different (concurrency or an honest constant, not a counter).
This makes the R0117 argument *stronger* than proposed: the real aliasing envelope is set by an
8.28 s and a 4.32 s poller, neither of which is its configured value.

### A second defect found by the pilot and fixed in the same run (L1.40)

`run_recorder_bybit.py` captured `now = time.time()` **once**, before a 20-symbol serial fetch loop,
and stamped every symbol's trade and meta batch with it. So every symbol after the first carried a
receipt stamp **earlier than the moment we received it** — a look-ahead in our own receipt axis,
the same class as the R0060 leaky Upbit copies. Measured across the archive before the fix:
**32.8% of 877,314 batches had a receipt stamp preceding the newest trade inside them.** Each batch
is now stamped at its own receipt; the meta rows share one stamp taken after their single fetch,
which is correct because one call serves every symbol. After the fix the fence reports
**neg = 0.0%** on the live Bybit Δ series.

## The free retrospective pilot, and its honest reading

Bybit trade batches carry our receipt on the outer row and the venue's `time` on every inner trade,
so Δ was measurable across the whole existing archive at zero collection cost — **877,314 batches**.

```
DELTA (recv - newest venue trade), ms
  p01=-4353  p25=-481  p50=1517  p75=7829  p90=20465  p99=68850  max=501340
  p99-p50 = 67333 ms          <- falsifier (1) rejects if < ~50ms: does NOT fire
  NEGATIVE deltas: 287,784 (32.80%)
```

Falsifier (1) does not fire, but **the dispersion is not evidence of a latency signal** and I am not
claiming it is. It is confounded four ways: true observation latency, trade-arrival gaps (the
per-symbol p50 tracks liquidity — TRXUSDT 12,265 ms vs NEARUSDT −907 ms), the stale-`now` stamping
bug above, and any venue/desk clock offset. **The existing archive cannot identify Δ.** That is the
pilot's real yield, and it is the argument for the build rather than against it: only the depth
path — receipt taken at true receipt, venue `ts` on the same record — gives a clean number. Live
after the fix: **fut p50 = 164 ms, Bybit p50 = 256 ms, negative share 0.0%.**

## A defect in the fence, caught by re-reading it (L1.40, UNMEASURED-REPORTED-AS-OK lens)

`unknown_streams` was computed, written into the artifact, and **never consulted by the status
ladder**. A brand-new venue directory would therefore have fallen through to `RECV-ONLY` — a
confident content verdict about a stream whose clock the fence cannot name. Fixed: an unclassified
stream now short-circuits the whole classification block and reports `UNMEASURED`.

The test for it then failed a second time on `recv_only_defects == []` — the *status* was right but
the artifact still **listed** the unknown stream as a defect, the same confusion one level down.
Both are now closed by a single `continue`. This is the exact class the desk names in L1.40
(UNMEASURED-REPORTED-AS-OK), found in a fence built to enforce it, in the same run — which is why
the doctrine says to expect it rather than to be surprised by it.

## Two instruments narrowed on their own first run

Both are recorded because the *narrowing* is the reusable lesson, not the fix:

1. The `moat_audit` regression test first checked for the coalesce as a **string**, and failed on
   the docstring where I quote the old line. Rewritten to check the AST **structurally**, so it
   catches the shape in any spelling.
2. That structural check then flagged `d.get("b") or d.get("bids")` — two spellings of *one*
   quantity, a legitimate coalesce. Narrowed to `cp.CLOCK_FIELDS` so it fires only on genuinely
   different **instants**. The instrument was narrowed rather than the code reworded to satisfy it:
   a check that fires on healthy code gets acknowledged into silence, and that is how enforcement
   actually dies.
